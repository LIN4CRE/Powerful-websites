# Contributing

Thanks for helping make the directory better. The most valuable contributions are
**genuinely useful websites that work without an account**, and **reports that a
listing has regressed**.

## Suggesting a website

Open a [site suggestion issue](.github/ISSUE_TEMPLATE/site-suggestion.yml) with:

1. the official URL;
2. one sentence describing what it does;
3. what you can do without creating an account;
4. the category you think fits.

Suggestions are queued as **candidates**, never published directly. The verifier
opens each one in a clean browser context and only promotes it when it passes.

## Reporting a broken or gated listing

Use the bug template and tick "The site now requires an account or no longer
works". Include the date and what you saw (login modal, paywall, error page).
The next scan will re-check it; a confirmed regression removes it from the
directory until it passes again.

## Adding a discovery source

Sources are data, not code. Append an entry to [`data/sources.json`](data/sources.json):

```json
{
  "id": "my-source",
  "name": "My Source",
  "type": "rss",
  "url": "https://example.com/feed.xml",
  "enabled": true,
  "category": "developer",
  "maxItems": 6,
  "notes": "Why this source is useful and how it is fetched."
}
```

Supported types: `github-awesome`, `github-search`, `no-signup-list`, `rss`,
`atom`, `html-links`. `html-links` sources honour `robots.txt`; GitHub sources use
the workflow's `GITHUB_TOKEN` and stay well inside rate limits. Run
`npm run scout` locally to try a source before opening a pull request.

## Editing descriptions

Descriptions in `data/sites.json` are generated by the pipeline and curated
automatically. If you want to improve one, edit the candidate's description in
`data/candidates.json` *before* it is verified, or open an issue with the exact
proposed wording. Descriptions must be original, factual and a single sentence.

## Code contributions

```bash
npm ci
npm run dev            # local site
npm run lint
npm run typecheck
npm test               # unit + data tests
npx playwright install chromium
npm run test:e2e       # browser tests (desktop + mobile)
npm run build
```

Guidelines:

- TypeScript everywhere, no `any` in application code.
- Keep the site dependency-light; do not add trackers, analytics or remote fonts.
- Never add credentials or tokens to the repository.
- Do not hand-edit `data/sites.json` to add a site. Use a suggestion or a source.
- Screenshots in a pull request are welcome when changing the design.
